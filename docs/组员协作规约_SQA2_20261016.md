## 2. 每日节奏与提交规范（git）

1. **每日 21:00 前 `git push`**（=当日进度打卡，连续两天无 push 组长会私聊）；
2. 单 main 分支＋小步提交：每完成一个小功能就 commit，不要攒一天；
3. 提交信息格式 `模块: 做了什么`（例：`library: 借阅上限校验`、`portal: 新闻列表页`、`docs: 测试计划初稿`）；
4. **push 前先 `git pull --rebase`**；冲突解决不了不要硬推，群里 @组长 仲裁；
5. **接口冻结纪律**：接口规范 10-17 12:00 升 v1.0 冻结。此后要改接口：群里提出 → 韦政治更新 `docs/接口规范` 并记变更行 → 消费方确认；**禁止只改代码不改文档**。联调期接口不符，以文档为准改代码；
6. 数据库 schema 变更权归韦政治（要在别人模块的表上加字段，群里提，不要自己改）。

## 4. AI 使用登记（每次都要）

用了任何 AI 工具（Copilot/Cursor/Claude/ChatGPT/ZCode 等），**当天**在仓库 `docs/AI使用登记.md` 末尾追加一行（格式照现有行：日期｜工具｜用途｜使用人），随代码一起 commit。交付时要按登记汇总《AI 与开源使用说明》（F-04），漏登=交付声明不实。

## 5. 红线（违反=返工+影响团队分）

1. `01_老师下发/` 只读——任何产出**不写进**老师材料目录；
2. 仓库**禁止提交**：老师下发材料、他组文件、`node_modules/`、`target/`、数据库备份、`.env`/本地配置（模板 `.example` 除外）、视频等大文件；
3. 不私改合同/验收口径（自然日 vs 工作日、违规确认制、隐私脱敏、诚信记录不可清除等已定口径见 AGENTS.md §3/§5）；
4. 诚信记录不提供删除接口（B 组硬口径，后端不写 DELETE）；
5. 敏感信息（数据库密码等）放 `application-local.yml`（已 gitignore）；
6. 正式提交件命名 `名称_SQA2`（组名不是公司名）；**作业4 文档必须 docx 格式**（10-16 课堂新规）。

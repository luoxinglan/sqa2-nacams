## 1. 通用约定（全接口必须遵守）

| 项 | 约定 |
|---|---|
| 基础路径 | `/api/v1`（前端只经 API 取数，**禁止直连数据库**） |
| 数据格式 | 请求/响应均为 UTF-8 JSON；文件上传用 multipart/form-data |
| 认证 | 登录返回 token，后续请求带 `Authorization: Bearer <token>`；**登录即自动签到、登出（logout）即自动签出**（A-03） |
| 角色 | `guest`（未登录，仅公开接口）/ `user`（注册用户）/ `admin`（系统管理员）；所长、图书管理教师=管理员在用户上设置的标记位 `isDirector` / `isLibrarian`（管理员按业务指定，3.5.A-9 口径） |
| 时间格式 | 一律 `"YYYY-MM-DD HH:mm"`（24 小时制，到分钟，与合同口径一致）；纯日期 `"YYYY-MM-DD"` |
| 统一响应包 | `{"code": 0, "message": "success", "data": ...}`；`code=0` 成功，非 0 失败 |
| HTTP 状态码 | 与 body `code` **同号镜像**（`code=0` → HTTP 200；401/403/404/409/422/500 原号返回）；前端统一按 body `code` 分支 |
| 分页 | 请求 `?page=1&page_size=20`；响应 `data = {"items": [...], "total": 123, "page": 1, "page_size": 20}` |
| 字段校验错误 | `code=422`，`data={"fields": {"字段名": "错误原因", ...}}`——前端据此在表单上逐字段提示 |
| 主要错误码 | 0 成功；400 参数错误；401 未登录；403 无权限；404 不存在；409 业务冲突（如超过在借上限，`message` 写明规则）；422 字段校验失败；500 服务器错误 |
| 隐私脱敏（B-07） | 服务端按角色输出字段：**游客/公开页可见=学号、姓名、邮箱、照片**；**电话、出生日期=仅本人和管理员可见**（列表接口对无权角色直接不返回该字段，前端不做"隐藏但传输"） |

## 2. 接口分工矩阵（谁提供、谁消费）

| 模块 | 提供方（后端） | 消费方（前端） |
|---|---|---|
| 认证账号、用户管理、批量导入、统计、内容管理 CRUD、媒体上传、备份恢复 | **韦政治** | 杨峥（管理员端）、刘罡甫/钟坤宇（公开页） |
| 图书借阅全流程、借阅配置、诚信记录、站内提醒、下载专区、用户帮助（A-06） | **陈彬** | 杨峥（注册用户端+管理员端） |
| 校验引擎、照片检测 | **陈彬**（校验规则同时做成后端共享库，韦政治在保存/导入路径调用） | 全部前端（表单预校验） |
| 首页聚合、门户内容查询 | **韦政治** | 刘罡甫（首页/登录页/简介）、钟坤宇（门户栏目） |

> 后端仓库内部建议：`backend/` 单仓库分模块（`auth/` `portal/` `library/` `admin/` `validation/` `backup/`），韦政治管框架与数据库（schema 变更权归韦政治），陈彬管 `library/` 与 `validation/`。

## 3. 接口明细（模块 × 方法 路径 ［权限］ 说明）

### 3.1 认证与账号（杨峥 UI ｜韦政治 BE）
| 方法 路径 | 权限 | 说明 |
|---|---|---|
| POST `/auth/login` | 公开 | `{username, password}` → `{token, user}`；登录即签到（记登录时间） |
| POST `/auth/logout` | user | 登出即签出（记登出时间） |
| GET `/auth/me` | user | 当前用户信息（含 isDirector/isLibrarian） |
| PUT `/me/profile` | user | 修改本人可改信息（敏感字段校验同 B 组规则） |
| POST `/me/photo` | user | multipart 上传本人照片；服务端保存前**强制过 B-05 检测**（≤2MB、宽高比 33:48，不通过返 422），成功返回新照片 URL（保存路径内部调用校验引擎；`/photos/check` 仅作前端体验性预检） |
| PUT `/me/password` | user | `{old, new}`；成功后当前 token 失效、需重新登录（重新登录即自动签到，无副作用）；管理员代重置走 `PUT /admin/users/{id}` 的 `resetPassword` 字段 |

### 3.3 图书借阅（杨峥 UI ｜陈彬 BE，规则=需求 §3.2.1.2.2）
| 方法 路径 | 权限 | 说明 |
|---|---|---|
| GET `/books?keyword=&page=` | user | 图书目录（编号 7 位=购买年份 4+顺序 3；基础数据 B001 风格由导入脚本换算） |
| POST `/books/{id}/borrow-requests` | user | 发起借阅；后端强制校验：同一图书仅一本、在借上限（默认 2，可配置）、违规≥3 次停借、归还 5 天内不可再借 |
| GET `/me/borrows` | user | 我的借阅：状态、应还日期、剩余天数、到期提醒标记 |
| GET `/admin/borrow-requests?status=` | librarian | 待审核借阅请求 |
| POST `/admin/borrow-requests/{id}/approve` \| `/reject` | librarian | 审核登记后借出/驳回 |
| GET `/admin/borrows?status=` | librarian | 在借工作视图：status=在借\|已超期\|已归还（含借阅人、图书、应还日期、超期天数）——催还与"超 30 天记违规"确认都从这里看 |
| POST `/admin/borrows/{id}/return` | librarian | **归还登记**：记录归还时间，启动"归还 5 天（自然日）内该书不可再借"冷却；超期未还由后台任务自动生成待确认违规（见 `/admin/violations`） |
| GET/PUT `/admin/library/config` | librarian | `{maxBorrow:2, loanDays:30, remindBeforeWorkdays:3}`——上限可由图书管理教师设置（F-03 可配置参数） |
| GET `/admin/violations?userId=&status=pending\|confirmed&page=` | librarian | 诚信记录＋**待确认队列**：pending=后台按"超 30 天（自然日）未还"自动生成的候选（生成时同时向图书管理教师发站内提醒——框架"再次提示"）；confirmed=已确认正式记录（**只增不删**——需求口径不可清除） |
| POST `/admin/violations` | librarian | 确认违规：把 pending 候选转为正式记录（**经图书管理教师在系统内确认**——合同 A-04⑨/框架 §3.2.1.2.2 原文，老师 3.5.A-8"先确认再记录"口径一致）；**不提供 DELETE** |
| GET `/me/violations` | user | 本人诚信记录（只读；被停止借阅时可查原因与已记次数） |
| POST/PUT/DELETE `/admin/books[/{id}]`、`/admin/books/import` | librarian | 图书新增/修改/删除/批量导入——图书域业务统一归图书管理教师（与借阅审核、归还登记、上限配置同域，UI 收进一个"图书管理"页）；admin 只负责授予 isLibrarian 标记 |

> 注：借阅"用户申请 → 图书管理教师审核登记 → 借出"两跳流程**源自需求框架 §3.2.1.2.2 原文**（"发起对未借图书的借阅请求，负责资料保管的教师审核请求后，给予登记备案后将图书借给请求发起人"），v0.2 所注"自定流程"作废。杨峥 UI 按"我的借阅可查审核状态"设计，演示走全流程，不加"代借"捷径。
